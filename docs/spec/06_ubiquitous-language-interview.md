# ユビキタス言語 ヒアリングシート（記入版）

## ブロック1 | アプリの本質を掴む

### Q1. このアプリで「一番解決したい瞬間」はどこか ★★★
* **回答:** 観光アプリで「観光名所・場所を検索したい、知りたい」という段階・タイミング。また、実際に調べて行きたいと思った時にルートがないと難しいため、ルート検索をして表示ができた瞬間。
* **出てきたキーワード:** 観光名所、検索、場所、ルート検索、表示
* **補足:** 受付の負担を減らしたいという背景がある。

### Q2. 観光・マナー・避難の3つ、どれが「なければ意味がない」か ★★
* **回答:** どちらが最悪なくてもいいかという点についてはまだ深まっていないが、強いて言えば「避難情報」の方が求められる。ただ、社会的な問題もあり優先順位はどちらも高く、ほぼ同列レベルで必要。
* **出てきたキーワード:** 避難情報、社会的（な問題）、優先順位、同列レベル

## ブロック2 | 観光ドメインの輪郭

### Q3. 「観光スポット」という言葉は使っているか。他の呼び方はあるか ★★★
* **回答:** 観光スポット以外であれば、「観光名所」「人気スポット」といった言い方になる。
* **出てきたキーワード:** 観光名所、人気スポット

### Q4. 観光スポットを見つけた後、ユーザーにどうしてほしいか
* **回答:** ルート、案内、経路の中であれば「案内」。サポートしてくれているというニュアンスが含まれるため。
* **出てきたキーワード:** 案内（サポート）
* **補足:** 「ルート」「経路」は少し堅く、指示されている印象を受ける（英語ならナビゲーション、デスティネーションなどもあるが、日本語のニュアンスとしては「案内」が選ばれた）。

### Q5. 複数の場所をまとめて案内するようなイメージはあるか ★★
* **回答:** ある。外国人観光客は1つだけではなく複数の場所を訪れたいため、機能として可能なら複数まとめて案内したい。その際のニュアンスは「プラン」か「コース」。スケジュールをガチガチに決める計画（日本語のプランのイメージ）よりは、流れるように誰かが決めてくれるような、パッと見て伝わりやすい「コース」のニュアンスも含まれる。
* **状況:** ある
* **出てきたキーワード:** プラン、コース
* **補足:** 現時点で言葉の定義に強いこだわりはなく、「プラン」「コース」どちらも選び得る・伝わりやすいという認識。

### Q6. 紹介したい場所に「種類」や「分け方」はあるか ★★
* **回答:** 分け方としては「ジャンル」や「属性」といったイメージ。
* **また、コンテンツの登録形態については「双方（運営からの提案とユーザーの自由なピン留め）」**だが、どちらかと言えば「もともと運営側で準備しているもの（観光案内所でよく聞かれる観光名所など）を強調・強めにしておく方が作りやすいし、案内しやすい」という方向性。
* **出てきたキーワード:** ジャンル、属性、近場
* **補足:** 曖昧な場所をピンポイントで押されても結局人に聞くことになるため、ベースは運営側の提案（プリセット）を主軸にしたい意向。

## ブロック3 | 避難ドメインの輪郭

### Q7. このアプリにおける避難情報の「役割」はどう考えているか ★★★
* **回答:** 普段はお守り的な存在。ただし、緊急時には画面（またはモード）が切り替わり、それを見たら完璧に避難できるような役割を持たせたい。
* **出てきたキーワード:** お守り的な存在、緊急時（の切り替え）、完璧に避難できる

### Q8. 「避難所」という言葉の他に、使っている言葉や種別はあるか ★
* **回答:** （明示的な単語の追加はなし。Q11にて「緊急避難経路」という組み合わせが浮上。）
* **出てきた言葉・種別:** 避難場所、避難所

### Q9. 避難所に「開いている・閉まっている」という状態はあるか ★★★
* **回答:** あってほしい（あったら便利）。
* **状況:** ある（あったら便利）
* **補足:** リアルタイムな満空情報の連携は開発の難易度が高いため、アプリ側で直接データを持つか、もしくは「公式の正確な情報が出ているサイトへのリンクを貼ってソースを促す」という方法も、一番正確な情報を出す手段としてありだと考えている。

### Q10. 避難所の「収容人数」はどういう数字か
* **回答:** 「使用人数（何人埋まっているか）」もあれば便利。
* **状況:** 未定（あれば便利だが、実装やデータ取得の実現性は要検討）

### Q11. 観光の案内と、避難への案内は「同じ体験」か「別の体験」か ★
* **回答:** 別の体験。緊急時なので「経路」という言葉のように堅苦しくていい。ただし、外国人の方に伝わるかを考慮する必要があるため、最悪単語を繋げて「緊急避難経路」のようなニュアンスで伝えてもいい。
* **状況:** 別の体験
* **出てきたキーワード:** 経路、緊急避難経路

## ブロック4 | マナードメインの輪郭

### Q12. 「マナー」と「ルール」は同じ意味で使っているか ★★★
* **回答:** 分ける方向で考える。
    * **ルール:** 本当に守らなければならないもの。
    * **マナー:** 周りの人が気持ちよく過ごせるように配慮するもの（例：ゴミのポイ捨てをされて嫌だなと感じるレベルのもの、暗黙の了解的なもの）。
* **状況:** 別
* **補足:** 明確に区別して定義したい意向。

### Q13. マナーは「場所によって違う」か「どこでも同じ」か ★★★
* **回答:** どちらも組み合わされている。日本としての普遍的なマナーもあれば、神戸市に合わせたマナー（例：エレベーターの乗り位置が左右どちらかなど）、あるいは特定の観光名所（神社の参拝の仕方など）に紐づくマナーも取り入れたい。
* **状況:** 両方の組み合わせ（普遍的 ＋ 地域・場所固有）
* **出てきたキーワード:** 神戸市にあったマナー、参拝の仕方

## ブロック5 | このシステムに関わる人を探る

### Q14. このアプリに関わる人を全員教えてほしい ★★★
* **出てきた人の種類 / 役割:**
    * **使う人（ユーザー / 外国人の方）:** アプリを使って観光名所やルートを検索したり、マナーを確認したり、緊急時に避難情報を確認する。また、外国人ユーザー側から「ここに公衆電話があった」などの情報を登録（投稿）し、他のユーザーがそれを知れるような仕組み（CGM/口コミ的な要素）も想定している。
    * **運営するサイド（運営サイド / 管理人）:** よく聞かれる観光名所や、ベースとなるコース・マナーなどのスポット情報をあらかじめ登録・管理する。

## 打ち合わせ後の記録欄

### 相手が自然に使った言葉（ユビキタス言語候補）

| 相手が使った言葉 | 文脈・意味 | 採用/要確認 |
| :--- | :--- | :--- |
| **観光名所** | 観光スポットや検索対象の場所を指す言葉 | **採用** |
| **案内** | ルートや経路よりも、ユーザーを「サポートする」ニュアンスの言葉 | **採用** |
| **コース / プラン** | 複数の観光名所をまとめて巡るための流れ・計画 | **採用**（どちらを主軸にするか要検討） |
| **ジャンル / 属性** | 観光名所やコースを分類するための軸 | **採用** |
| **お守り的な存在** | 平常時における「避難情報」の立ち位置・見え方 | **仕様に反映** |
| **緊急避難経路** | 緊急時において外国人にわかりやすく伝えるための、堅めの案内言葉 | **採用** |
| **マナー** | 相手が気持ちよく過ごすための配慮・暗黙の了解（ルールとは明確に分離） | **採用** |

### 使わなかった・避けた言葉
* **ルート / 経路（観光時）:** 指示されているようなニュアンスを感じるため、観光ドメインでは「案内」を優先する。
* **スケジュール:** ガチガチに予定を決めるイメージがあるため、流れるような表現ができる「コース」や「プラン」を好む。

### 次回深掘りすべき点
1. **ユーザー投稿機能のスコープ:** 外国人ユーザーが「公衆電話の位置」などを登録し、他ユーザーに共有する仕組み（Q14の後半）を、初期リリースにどこまで含めるか。
2. **避難所のリアルタイムデータ:** 「開閉状態」や「使用人数」のデータを、外部APIや既存のサイトリンクで補填するのか、システム側で管理するのかの具体的な線引き。
